# Проверка регистрации и входа — 30.09.2026

Проверены настоящий проект `ztimlpcqwbsxqfmetbpe`, опубликованный `https://flot-sector.netlify.app` и исправленный локальный клиент. Серверные ответы основного аудита не подменялись. Пароли и токены не включаются в этот отчёт.

## Подтверждено

- CORS: OPTIONS 204 с origin сайта; функция доступна. Пустой запрос возвращает ожидаемый 400.
- В базе нет аккаунтов без профиля, потерянных связей логина или ссылок на отсутствующего пользователя.
- Создание аккаунта с логином в верхнем регистре и пробелами по краям; подтверждение создания профиля новой формой.
- Пароль с латиницей, кириллицей и знаками; пароль не меняется при обработке логина.
- Повторная регистрация занятого логина: 409, без замены существующего аккаунта.
- Неверный пароль: 401, сессия не создаётся; последующий правильный вход успешен.
- Вход после выхода возвращает тот же UUID и профиль; регистр логина не важен.
- Изменённый позывной сохраняется после перезагрузки и виден во втором браузере. Позывной не заменяет логин.
- Опубликованный сайт принимает вход по логину и через email-ветку для того же тестового аккаунта. Чужие старые email-аккаунты без их паролей не проверялись.
- Мобильный Chrome (390×844, touch): вход, повторная загрузка, профиль, регистрация второго игрока по приглашению и присоединение к комнате; URL сохраняется.
- Ранее отдельным реальным тестом подтверждены сохранение баланса/карточки во втором браузере и возврат в комнату по `?room=…` после выхода и входа.

## Найдено и исправлено в клиенте

1. Нативный `pattern` отклонял логин с пробелами по краям до нормализации. Теперь единая проверка обрезает пробелы и указывает код недопустимого символа, включая невидимые символы.
2. `maxlength=24` мог обрезать вставленный логин до удаления пробелов. Поле теперь допускает полный ввод, ограничение 3–24 проверяется после нормализации и повторно на сервере.
3. Защита от повторной отправки теперь синхронная (`useRef`), а не только состояние кнопки React. Тест двух submit в одном такте подтверждает один запрос.
4. Конкурирующие загрузки профиля могли перезаписать введённый позывной старым ответом. Запоздалые результаты теперь игнорируются. Сохранение подтверждается получением обновлённого nickname из базы; пустой UPDATE не выдаётся за успех.
5. Уведомление об успешном входе очищается при выходе.

## Проверки

`npm test`: 76 тестов прошли. `npx playwright test e2e/login-ui.spec.ts`: пять сценариев ввода, двойной отправки, ошибок сервиса/сети и WebGL-fallback прошли. Сбои сети здесь моделируются явно; реальный сценарий ниже использует настоящий Supabase.

```powershell
$env:LOGIN_AUDIT='1'
npx playwright test e2e/auth-audit.spec.ts
Remove-Item Env:LOGIN_AUDIT
```

Расширенный аудит прошёл после исправления профиля. Он создаёт два реальных тестовых аккаунта и расходует три попытки регистрации, включая проверку занятого логина. Не запускайте многократно подряд: сервер сохраняет защиту от частых регистраций. Дополнительный аккаунт первого прерванного прогона оставлен без удаления других данных.

`npm run build` проходит. Проверенная сборка: `dist/assets/index-CtngLOOV.js`. На момент проверки сайт загружал `index-CsOn-lZP.js`: для исправлений формы и профиля **нужно загрузить всю новую dist в Netlify Drop**. Новых SQL-миграций или изменений секретов в этом аудите нет.

Проверки не дают гарантии отсутствия любых будущих сбоев интернета или сервиса. Подтверждены перечисленные сценарии; отдельной возможности восстановления забытого пароля у тестовых логинов без почты пока нет.
