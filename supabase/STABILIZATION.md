# Стабилизация сетевого боя — 1 октября 2026

## Найденные причины

- `Duel` опрашивал RPC каждые 2 секунды и блокировал поле флагом `busy` даже при чтении. Подписки отсутствовали.
- В рабочей базе не было `fleet_emote`: миграция 006 оставалась только в репозитории. **006 применена**, сообщение сопернику проверено на Netlify двумя реальными аккаунтами.
- Меню эмоций находилось в потоке `board-tools` только одного поля. Открытие увеличивало высоту правой колонки.
- Пушка запускалась через `useShotSound` только в `App` (бот), а `Duel` не обращался к аудиопровайдеру. На опубликованном сайте чайки воспроизводятся, пушка при сетевых выстрелах не запускается.
- Сетевые карты были отключены явно: RPC `fleet_duel` не принимал команды карт. Магазин при этом продавал карты для бота.
- Возврат из магазина всегда открывал `game`, то есть бота. Маршрут хранился только в React, без истории браузера.
- Реальный ответ 400 при реванше: `Round changed`, операция `fleet_emote/read`, старый раунд 1. Это гонка старого опроса эмоций со сменой раунда, а не ошибка регистрации или отсутствующая миграция. Новый клиент запрашивает актуальное состояние комнаты и не воспроизводит устаревшее событие.

## Изменения в новой сборке

Одна приватная подписка `duel:<uuid>` с проверкой членства. База отправляет только ревизию комнаты или подтверждённый ID эмоции. Таблица со скрытыми флотами **не публикуется**. Клиент перечитывает персональный снимок через RPC. При потере канала есть резервное чтение, при возврате на вкладку — сверка. Фоновое чтение не блокирует выстрелы. Обработчики освобождаются при уходе из комнаты; новое подключение ждёт завершения удаления старого канала.

Серверные карты используют существующий `fleet_wallets`, блокировку комнаты и кошелька в одной транзакции. UUID запроса защищает от повторного списания. Ошибка полностью откатывает операцию.

| Карта | Результат | Ход |
|---|---|---|
| Гидролокатор | Количество непоражённых сегментов в 3×3, без точных клеток | Сохраняется |
| Второй шанс | Следующий обычный выстрел не передаёт ход при промахе; бонус расходуется и при попадании | Сохраняется один раз |
| Перехват сигнала | Контур одного случайного ещё не раскрытого непотопленного корабля, без попаданий | Сохраняется |
| Глубинная бомба | Выстрелы по необстрелянным клеткам 2×2 | Сохраняется при любом попадании, иначе передаётся |
| Кракен | Один случайный непотопленный корабль, проверка победы | Сохраняется |

Отдельные настройки: море/чайки, боевые эффекты, эмоции. Общий выключатель сохранён. В последующем визуальном проходе добавлены 18 готовых мужских реплик и три лицензированных морских эффекта; они проигрываются через общий Web Audio без runtime-генерации. Источники: `public/audio/CREDITS.txt`.

Меню эмоций вынесено за поля. Вся анимация поверх сцены имеет `pointer-events:none`. Оба заголовка/панели управления сохраняют одинаковую высоту. На телефоне кнопка размещается под полями, меню не перекрывает клетки. URL хранит экран и комнату, поддерживается Back, возврат в бой и ввод приглашения кодом/ссылкой.

После подтверждения владельцем выполнить из корня проекта:

```powershell
npx --yes supabase db query --linked --project-ref ztimlpcqwbsxqfmetbpe --file supabase/migrations/202609300008_live_battle.sql --output json
```

Альтернатива — выполнить **только содержимое 008** через SQL Editor этого же проекта. Файл содержит транзакцию. Не выполнять все старые миграции повторно и не делать слепой `db push`: у существующей базы нет истории CLI-миграций.

Списанные при успешном применении карт экземпляры не возвращаются, результаты матчей не удаляются. Старые клиенты не отображают новые бонусы: после применения 008 нужна новая сборка для обоих участников.

Новая Edge Function и новые секреты не нужны. Auth, RLS профилей и регистрация не изменяются. Приватность подписки проверяется политикой `duel_notifications` в `realtime.messages`; отправлять собственные Broadcast-результаты клиенту не разрешено.
