# Флот: Сектор 10

Браузерный морской бой против бота: React, TypeScript, Vite, React Three Fiber и Supabase Auth. Корабли, вода, акулы и единый ландшафт созданы кодом; готовых 3D-моделей нет. Иллюстрации карт и два MP3 предоставлены пользователем.

## Тестовый баланс

На время тестирования стартовый баланс — **5555 жетонов**. Старый гостевой кошелёк при открытии приложения однократно получает баланс 5555; предметы и история сохраняются. Маркер `testingGrant: 1` предотвращает повторное восстановление потраченных денег при перезагрузке.

Для зарегистрированных игроков выполните `supabase/migrations/202609300003_testing_tokens.sql` после предыдущих миграций. Она однократно устанавливает 5555 в существующих кошельках и меняет начальный баланс новых. Без подключения к Supabase изменения на реальном сервере не применены. Описанные ниже 350 жетонов — прежний обычный стартовый баланс, временно заменённый тестовым.

## Магазин и усиления

Исправление панели карт: скрывавшая панель и применение проверка классического режима удалена. Существующий кошелёк остаётся общим для магазина и боя. Проверены 41 модульный тест и 26 браузерных сценариев (4 новых сценария карт и 22 существующих), production-сборка проходит. Новый путь включает покупку всех пяти карт, их применение, отмену, двойной клик, границы областей, продолжение после перезагрузки и победу от Кракена. Проверена изоляция локальных кошельков гостя и аккаунтов; реальный Supabase не настроен, серверное сохранение не проверено. Снимки: `artifacts/ability-kraken-desktop.png`, `artifacts/ability-mobile.png`.

Добавлены локальный гостевой кошелёк, магазин, шесть эмоций и пять расходуемых карт. Карты доступны в каждой партии с ботом, включая ранее сохранённые классические партии. В шапке — KZ / RU / EN и баланс. Нажатие на поставленный корабль поворачивает его; ближайшая допустимая позиция подбирается без перемещения остальных кораблей. Кнопка поворота и R сохраняются. Одноклеточный катер остаётся в той же клетке.

Новый кошелёк получает 350 жетонов, завершённая победа — 80, поражение — 35. Прерванная партия не награждается. Идентификаторы результатов предотвращают повторное начисление при перезагрузке. Очистка данных браузера удаляет гостевой кошелёк. Платежей нет.

Магазин содержит разделы «Эмоции», «Карточки», «Мои предметы». До четырёх купленных эмоций можно добавить на боевую панель. «Скрыть эмоции» доступно в магазине и панели правил/настроек. Изображения создаются SVG; для замены положите свой файл в `public/assets/shop` и добавьте соответствие ID → URL в `src/shop/artwork.json`, например `"sonar": "/assets/shop/sonar.webp"`.

Панель «Карты способностей» видна в каждой партии с ботом. Применение доступно только в ваш ход. Выберите карту: для гидролокатора и бомбы наведите указатель на **верхнюю левую клетку** области и нажмите по полю противника. На телефоне первое касание показывает область, второе подтверждает. Для остальных карт нажмите «Применить карту». Выход области за границы отклоняется без расхода. Уже обстрелянную клетку можно выбрать как начало области. «Отмена» или Esc возвращает обычную стрельбу без расхода карты.

| Карта | Цена | Правило |
| --- | ---: | --- |
| Гидролокатор | 180 | Число целых сегментов в 3×3, без точных координат; сохраняет ход |
| Второй шанс | 240 | Следующий выстрел сохраняет ход даже при промахе; попадание тоже расходует бонус; бонусы не складываются |
| Перехват сигнала | 450 | Контур случайного ещё не раскрытого живого корабля на поле противника; без урона, сохраняет ход |

Бонус «Второго шанса» сохраняется до следующего обычного выстрела, в том числе после перезагрузки; другие карты его не расходуют. Потопления и победа проходят через общие правила. Бот получает только историю выстрелов. Эффекты: сканирующий сектор гидролокатора, световые дуги бонуса, рамка перехвата, падающая бомба со всплеском, процедурные щупальца Кракена и погружение корабля. На мобильном меньше частиц и щупалец; при уменьшении движения остаются сообщения и отметки результата.

Архитектура обновления:

- `src/abilities.ts` — действия карт, результаты и поворот; сцена не рассчитывает урон.
- `src/shop/economy.ts`, `store.ts` — кошелёк, инвентарь, награды. `navigator.locks` сериализует гостевые покупки между вкладками. Основной снимок `fleet:wallet:v1:<guest|userId>` содержит инвентарь и игру: расход карты и результат записываются вместе. Прежний ключ игры используется для миграции и остаётся совместимым экспортом.
- `src/shop/Shop.tsx`, `catalog.ts`, `shop.css` — каталог и покупки; `artwork.json` — заменяемые иллюстрации.
- `src/i18n.tsx`, `translations.ts` — общий словарь с подстановками и язык. Старые журналы переводятся при отображении. Выбор сохраняется; стартовый язык — русский.
- `src/scene/AbilityEffect.tsx`, `Vessel.tsx`, `Board.tsx` — декоративные эффекты, поворот, контуры и выбор цели.

### Серверный магазин

В этом окружении имеется только `.env.example`: **реальная регистрация, серверный кошелёк и покупки не проверены**. Выполните обе миграции из `supabase/migrations` по порядку, заполните `.env.local` публичным URL/ключом и настройте Email Auth/Redirect URLs по инструкции ниже. `service_role` нельзя передавать в браузер.

Миграция `202609300002_shop.sql` добавляет `profiles.language` и кошельки с RLS. RPC `fleet_shop` проверяет владельца, каталог, цену и баланс, блокирует строку кошелька и обновляет её атомарно. Повтор UUID операции не оплачивается повторно. Ожидающий серверный запрос сохраняется для восстановления после сетевого сбоя. При недоступности сервиса аккаунт не подменяется гостевым кошельком.

Матчи с ботом остаются клиентскими: RPC **не проверяет честность результата одиночного боя**. Жетоны не имеют денежной стоимости. Для соревновательного мультиплеера потребуется серверная игровая модель и проверка действий; способности для сетевых матчей не включены.

Ручной путь проверки: гость → магазин → купить по одной карте → начать или продолжить бой с ботом → применить каждую карту из панели над полями → проверить результат и уменьшение количества → обновить страницу и продолжить. Проверьте отмену через Esc, область у правого нижнего края и бонус «Второго шанса» после перезагрузки. Откройте магазин в двух вкладках и попробуйте потратить один баланс одновременно. Для аккаунта повторите путь после настройки Supabase; дополнительно проверьте баланс со второго устройства и язык профиля.

Проверка обновления: production-сборка успешна, 35 модульных тестов прошли. В общем браузерном прогоне прошёл 21 из 22 сценариев; старый установщик тестовой партии обновлён для общего снимка кошелька, и оставшийся сценарий сцены прошёл отдельный повторный запуск. Проверены две полные партии в пути магазина, все пять карт, повторная награда, покупка из двух вкладок, три языка, мобильное управление и прежняя игра. Скриншоты: `artifacts/shop-desktop.png`, `artifacts/shop-kazakh-mobile.png`, `artifacts/boosted-battle.png`. Замер Chrome headless показал около 30 кадров/с для полей и 0 фоновых кадров при остановленной анимации; мобильная проверка использует эмуляцию 390×844 и замедление CPU ×4, не физический телефон.

## Игра и сохранения

На стартовом экране нажмите «Играть без регистрации». Разместите корабли вручную либо автоматически, при необходимости поверните выбранный корабль. Между кораблями должна оставаться свободная клетка, включая диагонали. Попадание сохраняет ход, промах передаёт его. На телефоне сначала выберите клетку, затем подтвердите действие кнопкой под полем. «Крупные клетки» увеличивают поле с горизонтальной прокруткой.

Гостевая партия сохраняется в прежнем ключе `fleet-sector-10:v1`, версия формата 1. Вход в аккаунт не переносит и не стирает её. Незавершённая личная партия сохраняется отдельно: `fleet-account:<user-id>:v1`. Завершённые личные партии отправляются в базу; очередь неотправленных результатов хранится в `fleet-results:<user-id>:v1`. Отправка повторяется при восстановлении сети, открытии игры и обновлении профиля. Пара `(user_id, id)` исключает дублирование результата после перезагрузки. При недоступном localStorage интерфейс предупреждает о невозможности сохранения.

В профиле можно изменить позывной, увидеть почту, общее число побед и поражений и последние 100 партий. Почта хранится в Supabase Auth, позывной и история — в таблицах проекта. Продолжение незавершённой партии между разными устройствами пока не реализовано. Статистика одиночной игры отправляется клиентом; это не защищённая от подделки соревновательная таблица.

## Настройка Supabase

1. Создайте проект Supabase. В SQL Editor выполните `supabase/migrations/202609300001_accounts.sql` один раз в новом проекте. Миграция создаёт `profiles`, `matches`, индексы, триггер создания профиля и RLS-политики.
2. В Authentication включите вход Email/Password и подтверждение электронной почты. Настройте SMTP для доставки писем вне ограничений тестовой почты сервиса.
3. В URL Configuration укажите Site URL приложения и добавьте разрешённые Redirect URLs: `http://127.0.0.1:5173/` для разработки и точный HTTPS-адрес опубликованного приложения. После подтверждения адреса клиент восстанавливает сессию из ссылки.
4. Скопируйте `.env.example` в `.env.local`. Заполните `VITE_SUPABASE_URL` адресом своего проекта, `VITE_SUPABASE_PUBLISHABLE_KEY` — публичным publishable key (либо legacy anon key). Перезапустите Vite. При публикации задайте эти переменные перед сборкой.
5. Не используйте service_role, secret key, пароль базы или JWT secret в переменных `VITE_*`: они попадают в браузер. Локальные `.env*` исключены из Git; в репозитории только пустой шаблон.

Доступ к данным обеспечивается RLS на сервере, а не проверкой localStorage. `anon` не имеет доступа к личным таблицам. Вошедший пользователь читает только свои строки, меняет только свой nickname и добавляет только свои результаты. Изменение/удаление истории через клиент не разрешено. Восстановление сессии и обновление токена выполняет официальный SDK; выход завершает сессию текущего устройства.

Официальная документация: [Supabase Auth для React](https://supabase.com/docs/guides/auth/quickstarts/react), [регистрация](https://supabase.com/docs/reference/javascript/auth-signup), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

### Что нужно проверить на подключённом проекте

В текущем окружении нет URL, публичного ключа и тестовой почты Supabase. Реальная регистрация, доставка письма, вход/выход, восстановление авторизованной сессии и SQL/RLS на сервере НЕ проверены.

После настройки зарегистрируйте тестового пользователя, откройте письмо и подтвердите почту; войдите и обновите страницу. Измените позывной, завершите партию, проверьте историю и отсутствие дубликата после перезагрузки. Выйдите и убедитесь, что прежняя гостевая партия доступна. Создайте второго тестового пользователя: через SDK его сессия не должна читать/изменять профиль и историю первого пользователя; запрос без сессии тоже не должен возвращать личные данные. Проверьте неверный пароль, неподтверждённую почту и временное отключение сети.

## Единая композиция

`src/scene/World.tsx` — одна фоновая 3D-сцена всей страницы. Сверху — небо и дальние горы в тумане; слева — близкий берег и один маяк; справа — другая островная гряда. Общая вода продолжается за интерфейсом и по бокам. Фон закреплён относительно окна и не перехватывает ввод; нижний цвет страницы совпадает с затуханием фона. Повторяющиеся полосы скал внутри полей удалены.

`src/world.css` задаёт контейнер с боковыми просветами, одинаковые поля, панель сводки и стартовые формы. На телефоне верхний отступ уменьшен, показывается один выбранный сектор. Положение клеток задаёт `src/scene/projection.ts`; правила в `src/game.ts` не зависят от сцены. Качка, пена, акулы, орудия, самолёты и экипаж в увеличенном виде сохранены.

Для читаемости вода игрового поля остаётся плоской: движение волн имитируется шейдером. Фон использует сглаженную простую геометрию, дистанционный туман и прозрачный луч без объёмного расчёта света и тяжёлых теней. На телефоне убран один ближний остров и снижена частота обновления фона. Спокойный режим и системное уменьшение движения останавливают декоративную анимацию. Игровые поля ограничены 30/24 кадрами в секунду; слабый мобильный профиль автоматически останавливает движение при длительном падении ниже 17 кадров/с.

## Ограничения

Фиксированная игровая камера, одиночный бот, без мультиплеера и платежей. Для 3D нужен WebGL. Корабли противника скрыты до потопления; перехват сигнала может показать контур одного корабля. Локальная игра не защищает скрытые данные от инструментов разработчика. Сборка предупреждает о крупном JS-пакете с Three.js и Supabase SDK; это не ошибка компиляции.

## Живой главный экран

`src/scene/Harbor.tsx` добавляет отдельный вариант фона стартового экрана: террасированные берега с цветами слоёв породы, группы хвойных деревьев через instanced meshes, объёмную луну с ореолом, вращающийся фонарь и затухающий луч маяка. Тёплое освещение берега дополняет движущийся блик на воде. У моря есть медленная деформация поверхности, процедурная рябь, лунная дорожка и береговая пена. Декоративный эсминец движется по замкнутому маршруту с качкой и кильватерным следом; он не получает состояние партии.

Карточка непрозрачна и расположена над сценой; фон не перехватывает события указателя. Вариант фона игровых полей сохранён. ## Обновление маяка, уровней бота и профиля

- `src/scene/beacon.ts` задаёт единый источник и вектор света. `Harbor.tsx` использует его для ротора, конуса, прожектора и шейдера воды. Три луча пересечения с геометрией ограничивают дальность у скал (на телефоне один центральный луч). Это упрощённое консервативное перекрытие: весь пучок сокращается по ближайшей преграде, без тяжёлого объёмного освещения. Дальний лунный диск имеет мягкий край, ореол и несколько широких пятен поверхности вместо клетчатой сферы; звёзды неподвижны.
- `src/bot.ts`: Новичок выбирает случайную свободную клетку; Тактик добивает попадания и продолжает обнаруженную линию; Адмирал считает допустимые размещения оставшихся длин, исключает промахи и соседство потопленных кораблей. Вход алгоритма — только открытая история выстрелов. Выбор хранится в `fleet:difficulty`, сложность текущей партии — в её сохранении. Старые партии используют Тактика.
- `src/App.tsx`: выбор уровня до боя, отображение уровня во время боя, кнопка поворота и клавиша R вне полей ввода. Недопустимый поворот показывает сообщение; существующий флот сохраняется. Предпросмотр и сенсорное подтверждение используют прежние правила клеток.
- `src/account/Entry.tsx`, `Profile.tsx`, `client.ts`: после входа открывается профиль; показаны дата регистрации, число сыгранных партий, победы и поражения. Пока загрузка не завершилась, статистика показана прочерками, а не выдуманными нулями. Кнопка профиля добавлена в шапку вошедшего игрока. Доступ определяется сессией Supabase; у гостя форма профиля не отображается. При отсутствии/ошибке конфигурации гостевой режим работает, в форме есть инструкция подключения.

### Ручная проверка пяти частей

1. Откройте главную страницу с `?diagnostics=1&beamAngle=0`, затем `1.5707963267948966`, `3.141592653589793`, `4.71238898038469`. Это фиксирует четыре направления для визуальной проверки. Обычная страница вращает луч плавно. Снимки: `artifacts/beacon-quarter-0.png` … `beacon-quarter-3.png`.
2. Посмотрите луну над правой грядой и на экране шириной 390 px. Снимок телефона — `artifacts/moon-mobile.png`. Включите системное уменьшение движения: сцена остаётся статичной.
3. Нажмите «Играть без регистрации», выберите каждый уровень в списке «Сложность бота» до начала операции. После новой игры и перезагрузки выбор должен сохраниться. Тесты выполняют по три полные партии каждой сложности и отдельную браузерную партию каждого уровня; браузерные таймеры бота ускорены средствами Playwright, правила и реальные кнопки не подменяются.
4. Наведите корабль у края поля и нажмите R; при невозможном размещении появится предупреждение и красный предпросмотр. На телефоне используйте «Повернуть» и отдельную кнопку подтверждения размещения. Ранее поставленные корабли не должны исчезать.
5. Заполните `.env.local` и выполните имеющуюся SQL-миграцию по инструкции выше. Затем зарегистрируйтесь, подтвердите почту, проверьте открытие профиля, дату регистрации, изменение позывного, результат завершённой партии, обновление страницы и выход. Реальное подключение и RLS в данном окружении всё ещё не проверены: предоставлен только `.env.example`, URL/публичного ключа проекта нет. Ни пароли, ни фиктивные аккаунты локально не создаются.
